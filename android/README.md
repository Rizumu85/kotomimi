# Kotomimi 手机端

把一台安卓手机借给电脑上的 Kotomimi 做语音识别：声音从电脑传过来，手机识别，文字传回去。

识别引擎和电脑版是同一个（[audio.cpp](https://github.com/0xShug0/audio.cpp) 0.9.0），模型也是同一批文件。

自检时还会用另一个引擎（[llama.cpp](https://github.com/ggml-org/llama.cpp) b11401）把同一个模型再读一遍，看哪个在这台手机上更快。借给电脑用的始终是 audio.cpp。

## 给朋友测

1. 装上 `app-debug.apk`（要允许"安装未知来源的应用"）。
2. 下载模型（建议连 Wi-Fi；断了可以接着下）。列表里同一个模型有两行：写着"audio.cpp 用"的是借给电脑时用的，写着"llama.cpp 用"的只在自检里拿来对比（它是两个文件，一个接一个下）。要比两个引擎，就把同一个模型的两行都下了：0.6B 两行一共 2.0 GB，1.7B 两行一共约 4.7 GB。在国内不用开代理：模型在 Hugging Face、魔搭（ModelScope）和一个 Hugging Face 的公开镜像上各有一份，开始时各试一小段，哪边快用哪边；分四路同时下，下面会写着进度、速度和来源。中途断了会自己接着下，不用再点。下完会核对。
3. 自检之前：拔掉充电线，关掉省电模式，电量在一半以上；刚下完模型的话先放几分钟，让手机凉下来。
4. 点"自检"，把手机放在桌上别动：别切到别的 App，别锁屏。屏幕上会写着读到第几项、现在在等什么。读完把报告分享回来。
5. 自检说跟得上的话，点"开始共享"，照下面"和电脑连接"试一次真的。

自检要多久：每个模型、每个引擎要读 5 遍（4 线程两遍、6 线程两遍、显卡一遍），每遍之前先等手机凉下来，最少等 10 秒，最多等 3 分钟。所以一个模型两个引擎，凉得快的话四五分钟，一直凉不下来（天热、充着电、带着厚壳）就要半小时；两个模型都下了就翻倍。时间大半花在等上：2026-10-12 在多亲 F22 Pro 上（很慢的手机，插着线）测了两次 0.6B 两个引擎，一次 13 分钟（等了 9 分钟），一次 26 分钟（等了 22 分钟，十遍里六遍等满了 3 分钟）。快的手机上还没测过要多久。

报告里是这台手机自己的数字：芯片、内存、电量和是不是充着电，两个引擎每一遍读一段 14 秒录音用了多久、装入用了多久、占多少内存、读之前和之后的电池温度。不包含任何你自己的声音。

## 怎么看自检结果

倍速 = 一秒钟能读几秒的话。电脑版边听边出字，是把越来越长的同一段话反复读，所以：

- 4 倍以上：跟得上
- 2 到 4 倍：勉强
- 2 倍以下：跟不上

每个模型一块，两个引擎并排，比如 `4 线程：audio.cpp 2.52 / 2.41 倍速   llama.cpp 3.10 / 3.02 倍速`（斜杠两边是先后两遍）。下面一行写着哪个引擎的哪种设置最快、快多少（按两遍的平均算）。屏幕上那句"跟得上 / 跟不上"只看 audio.cpp 的数字，因为共享用的是它。

手机读过一遍会发热，热了就慢。所以每一遍之前，自检都等手机凉下来：电池温度回到开始时的 1°C 以内，或者已经 40 秒不再往下降（凉到头了，每一遍都从这同一个温度开始，一样公平），系统也不再说手机热；两个引擎轮流读（audio.cpp 4 线程、llama.cpp 4 线程、audio.cpp 6 线程、llama.cpp 6 线程，然后同样的再来一遍），谁也不会因为排在后面吃亏。等了 3 分钟还没凉下来就照样读，这一遍在报告里带 `*`。

两个引擎的计时算的是同一段：把录音读进来、听、写出字，不算装入模型。audio.cpp 自己报这个数；llama.cpp 不报，由 App 从它装完模型的那一行开始计到它结束。

2026-10-12 在多亲 F22 Pro（联发科 MT6769，4 GB，插着线）上，Qwen3-ASR 0.6B：audio.cpp 最快 0.58 倍速，llama.cpp 最快 1.05 倍速，都是 6 线程，都跟不上；内存 audio.cpp 占 2.0 GB，llama.cpp 占 1.7 GB；读出的字一样。两个引擎的显卡（Mali-G52）都一用就崩，报告里写的是"显卡：… 用不了"和引擎崩之前说的最后一句。别的手机上谁快还不知道，这正是要测的。

## 和电脑连接

手机和电脑在同一个 Wi-Fi 下。

**手机上**：点"开始共享"。屏幕上先是"正在装入"，然后是"等电脑连上"和一个地址，比如 `192.168.1.23:8792`。可以锁屏放在一边：通知栏里有一条"正在共享"，在那里也能停。

**电脑上**（Kotomimi 0.43.110 及以后）：设置 → 提供商，最上面「另一台设备」里点"搜索局域网里的设备"。手机会列出来，带手机图标，标着"手机 · 语音识别"。点它一下就连上了：语音识别这一个环节交给手机，翻译和语法反馈不变。

这样连是**边听边出字**，和电脑自己的引擎一样：说话时把到目前为止的这一段反复让手机重读。多久重读一次跟着手机读一次要多久走，所以看到的就是这台手机自己的速度。

搜不到时（比如路由器不让设备互相访问）可以手填：语音识别 → 「API 模型」，API 地址填 `http://<手机上显示的地址>/v1`，模型填 `qwen3-asr-0.6b-q8` 或 `qwen3-asr-1.7b-q8`，"这个 API 需要密钥"关着。0.43.109 及更早的电脑版只能这样手填，而且是一句话说完才出字。

自检里的"倍速"和实际体感的对应（用放慢的电脑引擎模拟的，20 秒日语，前 17 秒是一整段不停的话）：4 倍速时第一句译文比电脑自己的显卡晚约 7 秒，2 倍速晚约 11 秒，1 倍速晚约 29 秒；文字都完整，只是长句子的后半截落后。

共享用的是 audio.cpp，和自检给它找到的最快的方式（4 或 6 个线程，或者显卡）；没自检过就用处理器 4 线程。借出去哪个模型：下载了两个 audio.cpp 用的模型时，点一下那个模型。llama.cpp 用的模型借不出去。

手机只回答身边的设备：网页发来的请求、用公网域名指过来的请求都会被拒绝（和电脑版共享的做法一样）。现在没有访问密钥，同一个 Wi-Fi 下的设备都能让它识别。

## 自己编

要 Android Studio（带 SDK、NDK 和它的 CMake）；Windows 上还要 Visual Studio 的 C++ 编译器（显卡后端的着色器要用它编一个小工具）。

```bash
# 1. 引擎：从 audio.cpp 的源码编出安卓版，放进 App 里（十几分钟，不进 git）
android/scripts/build-engine.sh

# 2. 自检里对比用的 llama.cpp：编出它的四个版本，放进 App 里（十分钟左右，不进 git）
android/scripts/build-llama.sh

# 3. 安装包
cd android && ./gradlew assembleDebug
```

安装包在 `android/app/build/outputs/apk/debug/app-debug.apk`，约 43 MB，其中 llama.cpp 占 22 MB（处理器三档各 3.7 MB，显卡那个 10.6 MB）。不跑第 2 步也能编出安装包，只是自检里没有 llama.cpp，报告里会写"这个安装包里没有带"。

引擎带齐了 ggml 给安卓准备的七档处理器版本（armv8.0 到 armv9.2），运行时自己挑这台手机能用的最快一档，所以同一个安装包在旧手机和新手机上都不吃亏。显卡后端（Vulkan）也编进去了，但只在要用它的那一次才加载：有的手机驱动撑不住它，这样崩掉的只是那一次，处理器照常能用。

llama.cpp 这边是四个各自独立的程序（`llama-mtmd-cli`）：处理器三档（v80、v82、v86）和显卡一个（Vulkan）。它不会在运行时自己挑，所以由 App 看处理器报的指令集来挑：有 dotprod 和 fp16 用 v82，再加上 i8mm 和 bf16 用 v86，否则 v80。挑的那一档要是一跑就报"非法指令"，就退一档再读，报告里会写。它的 `libggml*.so` 和 audio.cpp 的同名却不是同一个版本，放不进同一个文件夹，所以编成不带库的单个程序。

App 给 llama.cpp 的上下文定在 1024（`-c 1024`）。不定的话它按模型训练时的 65536 留内存，多出两个多 GB：在 4 GB 的手机上，系统为了腾地方把后台的 App 连同这个 App 一起关掉了（2026-10-12）。

从电脑上直接让手机做事：

```bash
adb shell am start -n io.github.rizumu85.kotomimi.node/.MainActivity --ez selfcheck true
adb shell cat /sdcard/Android/data/io.github.rizumu85.kotomimi.node/files/report.txt
adb shell am start -n io.github.rizumu85.kotomimi.node/.MainActivity --ez share true
curl http://<手机地址>:8792/v1/models

# 自检时先用 llama.cpp 的某一档（v86、v82、v80），而不是它自己挑的：看退档那条路用的
adb shell am start -n io.github.rizumu85.kotomimi.node/.MainActivity --ez selfcheck true --es llama v86
```

## 手机对外提供什么

端口 8792（故意不用电脑版共享的 8790：现在发布的电脑版会搜 8790，搜到手机就会把它当成一台有整条管线的设备列出来，选了却连不上）：

- `GET /v1/models`：借出去的那个模型。回答里带 `X-Kotomimi-Name`（手机的名字）和 `X-Kotomimi-Node: engine`（这里是识别引擎本身，不是一台电脑的整条管线）。
- `POST /v1/audio/transcriptions`：一段声音整段读一遍，原样转给引擎（OpenAI 的格式：`file`、`model`、`language`）。

引擎自己只听手机本机（127.0.0.1:8793），外面的请求都经过这层小门。

## 还没有的

- 内存不够时先说出来：4 GB 的手机读十几秒的长段时会被系统因内存不足杀掉（2026-10-10 在 F22 Pro 上）。
- 访问密钥。
- 小样里的样子（`.dev/phone-node/`，杏橙薄荷那一版）：现在只用了它的颜色。
- Nemotron 和 R2T2：引擎里已经编进去了，App 里还没列出来。
- 用 llama.cpp 共享：现在它只在自检里。自检要是说它明显更快，再做。
